# FormField

Wires label, description, control and error through generated ids and ARIA
attributes.

## Usage

```tsx
import {
  FormField,
  FormFieldControl,
  FormFieldDescription,
  FormFieldError,
  FormFieldLabel,
  Input,
} from "@raulrod/ui";

<FormField>
  <FormFieldLabel>Email</FormFieldLabel>
  <FormFieldDescription>We never share your email.</FormFieldDescription>
  <FormFieldControl>
    {(field) => <Input type="email" placeholder="you@example.com" {...field} />}
  </FormFieldControl>
  <FormFieldError>Invalid email address.</FormFieldError>
</FormField>;
```

When the `Error` slot is present, the control automatically receives
`aria-invalid="true"` and `aria-errormessage`.

## Slots

| Slot                   | Purpose                                                                                                        |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- |
| `FormField`            | Provider. Generates the control id and detects slot presence.                                                  |
| `FormFieldLabel`       | `<label htmlFor={id}>`.                                                                                        |
| `FormFieldDescription` | Helper text, referenced by `aria-describedby`.                                                                 |
| `FormFieldControl`     | Render-prop wrapper that spreads `{ id, aria-describedby, aria-invalid, aria-errormessage }` onto the control. |
| `FormFieldError`       | Error message. Adds `aria-invalid` and `role="alert"`.                                                         |

## Props

### `FormField`

- `controlId?: string` — override the generated id.
- Standard `HTMLAttributes<HTMLDivElement>` pass through.

### `FormField.Label`

Standard `LabelHTMLAttributes<HTMLLabelElement>`; `htmlFor` is forced.

### `FormField.Description`

Standard `HTMLAttributes<HTMLParagraphElement>`.

### `FormField.Control`

Accepts a React node or a function `(field: FormFieldControlProps) => ReactNode`.

### `FormField.Error`

Standard `HTMLAttributes<HTMLParagraphElement>`; renders with `role="alert"`.

## Accessibility

- `<label htmlFor={id}>` links the label to the control.
- `aria-describedby` includes the description id.
- `aria-errormessage` and `aria-invalid` are set when `FormField.Error` is
  present.
- The error message renders with `role="alert"` so it is announced on mount.

## Trade-offs / Limitations

- **Slots must be leaf siblings.** `FormField` detects slots by walking its
  direct children. Wrapping a slot inside another component hides it from the
  detection and leaves the field unlabeled/unannounced.
- **One control per field.** The pattern assumes a single id → single control.
  Groups of checkboxes or radios should use their own grouping components
  (RadioGroup) rather than FormField.
- **Render prop vs explicit slot.** You can pass a function as `FormField`
  children instead of using `FormFieldControl`, but this is sugar for the same
  single-control contract.
- **`aria-errormessage` support is not universal.** Some screen readers ignore
  it; for that reason the error also stays in `aria-describedby`.
- **No dot-notation API.** Unlike `Table` and its `TableHeader`/`TableBody`
  slots, `FormField` currently exports `FormFieldLabel`, `FormFieldControl`,
  etc. as separate named exports. The package root does not expose
  `FormField.Label`. This is a known inconsistency to resolve in the next
  API-facing epic (EPIC-13); RRU-142 only documents the current reality.
