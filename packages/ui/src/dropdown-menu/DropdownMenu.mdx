## Usage

`DropdownMenu` follows the same compound pattern as `Dialog` and `Popover`:

```tsx
import { DropdownMenu } from "@raulrod/ui";

<DropdownMenu>
  <DropdownMenu.Trigger>Actions</DropdownMenu.Trigger>
  <DropdownMenu.Content>
    <DropdownMenu.Item onSelect={() => console.log("copy")}>Copy</DropdownMenu.Item>
    <DropdownMenu.Item onSelect={() => console.log("paste")}>Paste</DropdownMenu.Item>
    <DropdownMenu.Separator />
    <DropdownMenu.Sub>
      <DropdownMenu.SubTrigger>More</DropdownMenu.SubTrigger>
      <DropdownMenu.SubContent>
        <DropdownMenu.Item>Export</DropdownMenu.Item>
      </DropdownMenu.SubContent>
    </DropdownMenu.Sub>
  </DropdownMenu.Content>
</DropdownMenu>;
```

## Accessibility

- `role="menu"`, `role="menuitem"`, `aria-haspopup`, `aria-expanded` and
  `aria-controls` are wired automatically.
- Roving focus with Arrow keys; Enter/Space activates an item and closes the
  whole tree.
- Submenus open with ArrowRight or pointer enter.

## Trade-offs / Limitations

- **Non-modal by design.** There is no focus trap, scroll lock or `aria-modal`.
  Tab leaves the menu; Escape or outside click closes it.
- **Neutral trigger styling.** `DropdownMenu.Trigger` renders a plain button by
  default. For the toolbar look, wrap it in `Button` or `IconButton`.
- **Type-ahead is basic.** Full search/filter is out of MVP scope; only
  single-character type-ahead is supported.
- **Submenus are always uncontrolled.** Only the root menu supports the
  controlled `open`/`onOpenChange` contract.
- **Slot presence matters.** Items must be direct children of `Content` (or
  `SubContent`) for the keyboard hook to discover them.

## Narrow viewports

Like `Popover`, the menu is `position: fixed` and portaled, so its width was
shrink-to-fit against the viewport: one long item label opened a panel wider than
the screen. The menu and every `SubContent` are now bounded (RRU-137):

```css
/* DropdownMenu.css — on .rr-dropdown-menu */
box-sizing: border-box;
max-inline-size: min(calc(var(--rr-space-16) * 6), calc(100vw - 2 * var(--rr-space-4)));
max-block-size: calc(100dvh - 2 * var(--rr-space-4));
overflow: auto;
```

- **A menu taller than the screen scrolls, and that scrollport is reachable.** It
  differs from the tooltip's on purpose: every item is a focusable `menuitem`, so
  <kbd>ArrowDown</kbd> walks focus through the scrollport and the browser scrolls each focused item
  into view. A long list needs no pointer to reach its end.
- **Long labels wrap inside the bound** instead of widening the panel, following
  the `overflow-wrap` policy RRU-136 fixed for layout primitives.
- **`box-sizing: border-box` again.** The menu's `space-1` padding would
  otherwise add to the clamp and push the panel past the bound it declares.
