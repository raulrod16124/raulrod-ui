## Usage

`Dialog` is a compound component. The root is a pure state provider; the DOM is
rendered by the slots:

```tsx
import { Button, Dialog } from "@raulrod/ui";

<Dialog>
  <Dialog.Trigger>Open dialog</Dialog.Trigger>
  <Dialog.Content>
    <Dialog.Header>
      <Dialog.Title>Confirm action</Dialog.Title>
      <Dialog.Description>This action cannot be undone.</Dialog.Description>
    </Dialog.Header>
    <Dialog.Footer>
      <Button variant="secondary">Cancel</Button>
      <Button>Confirm</Button>
    </Dialog.Footer>
  </Dialog.Content>
</Dialog>;
```

It can be used controlled (`open` + `onOpenChange`) or uncontrolled
(`defaultOpen`).

## Accessibility

- `role="dialog"` + `aria-modal="true"` on the content panel.
- `aria-labelledby` points to `Dialog.Title`; `aria-describedby` points to
  `Dialog.Description` only when the slot is present.
- Initial focus moves to the panel; `Escape` closes it and focus returns to the
  trigger.

## Trade-offs / Limitations

- **Composition over props.** Instead of `title`, `description` and `footer`
  props, the consumer composes slots. This keeps the API explicit and lets the
  consumer control layout, but it requires learning the slot names.
- **No generic `as` / `asChild`.** `Dialog.Trigger` is always a `<button>`.
  If you need an anchor that opens a dialog, wrap it and call the state via the
  controlled API.
- **Always modal.** There is no non-modal mode. For non-modal floating panels,
  use `Popover`.
- **Title is not strictly required at compile time**, but a dialog without
  `Dialog.Title` will fail the accessible-name contract and axe checks.
