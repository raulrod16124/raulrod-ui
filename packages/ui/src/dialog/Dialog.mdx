## Usage

`Dialog` is a compound component. The root is a pure state provider; the DOM is
rendered by the slots:

```tsx
import { Button, Dialog } from "@raulrod/ui";

<Dialog>
  <Dialog.Trigger>Open dialog</Dialog.Trigger>
  <Dialog.Content>
    <Dialog.Header>
      <Dialog.Title>Confirm action</Dialog.Title>
      <Dialog.Description>This action cannot be undone.</Dialog.Description>
    </Dialog.Header>
    <Dialog.Footer>
      <Button variant="secondary">Cancel</Button>
      <Button>Confirm</Button>
    </Dialog.Footer>
  </Dialog.Content>
</Dialog>;
```

It can be used controlled (`open` + `onOpenChange`) or uncontrolled
(`defaultOpen`).

### Sizing: the panel is bounded by the viewport, not by your content

`Dialog.Content` is `position: fixed` over the whole screen, so its size is decided
by the **viewport** rather than by whatever container you render it inside — a 320px
wrapper around a dialog changes nothing about how wide it opens. It is capped at
`28rem` (448px) and at the viewport height minus the overlay's own 24px gutter on
each side, which at a 360px-tall screen is 312px. Content taller than that scrolls
**inside the panel**, so the border, the title and the actions always stay on
screen.

The gutter and the cap are the same token, and they have to stay that way. The
overlay reserves `space-6` and the panel subtracts `2 × space-6`; when those two
numbers disagree the panel is allowed to be taller than the space it is centred in,
and a centred flex item that overflows its line does not shrink — it spills equally
off the top and the bottom.

The footer wraps. A row of long-labelled actions narrower than its labels does not
overflow: it wraps onto as many rows as it needs, each label on one line, instead of
squeezing every button until its own text wraps inside it.

## Accessibility

- `role="dialog"` + `aria-modal="true"` on the content panel.
- `aria-labelledby` points to `Dialog.Title`; `aria-describedby` points to
  `Dialog.Description` only when the slot is present.
- Initial focus moves to the panel; `Escape` closes it and focus returns to the
  trigger.

## Trade-offs / Limitations

- **Composition over props.** Instead of `title`, `description` and `footer`
  props, the consumer composes slots. This keeps the API explicit and lets the
  consumer control layout, but it requires learning the slot names.
- **No generic `as` / `asChild`.** `Dialog.Trigger` is always a `<button>`.
  If you need an anchor that opens a dialog, wrap it and call the state via the
  controlled API.
- **Always modal.** There is no non-modal mode. For non-modal floating panels,
  use `Popover`.
- **Sizing is not yours to set.** The panel is bounded by the viewport and the
  overlay's gutter; there is no width or height prop, by design. A dialog whose
  content must always fit without scrolling needs shorter content, not a taller
  screen — the cap is the same on every device.
- **Title is not strictly required at compile time**, but a dialog without
  `Dialog.Title` will fail the accessible-name contract and axe checks.
