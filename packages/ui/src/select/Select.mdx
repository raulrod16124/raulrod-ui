## Usage

`Select` is a read-only combobox with a floating listbox:

```tsx
import { Select } from "@raulrod/ui";

<Select defaultValue="apple">
  <Select.Trigger>
    <Select.Value placeholder="Pick a fruit" />
    <Select.Icon />
  </Select.Trigger>
  <Select.Content>
    <Select.Item value="apple">Apple</Select.Item>
    <Select.Item value="banana">Banana</Select.Item>
    <Select.Item value="orange" disabled>
      Orange
    </Select.Item>
  </Select.Content>
</Select>;
```

### Sizing: the listbox follows the field

The listbox opens exactly as wide as its trigger — **up to 384px**, and never wider
than the viewport minus 16px on each side. At a narrow width that means the panel
matches the field exactly; on a wide screen it stops at 384px rather than stretching
to 1024px, so a long option wraps into two lines instead of pushing the panel past
the screen edge. Options scroll **vertically** when there are more of them than fit,
which <kbd>ArrowDown</kbd> walks through.

Put the trigger in a container whose width you control (a grid cell, a form column)
and the listbox follows it, even though the panel is portalled to `document.body`:
`Select.Content` measures the trigger and writes that width before positioning. The
384px cap is what stops the other half — on a full-width field, a listbox matching
1024px would put every option on a single short line with the chevron stranded far
from the labels it points at.

## Accessibility

- Trigger renders `role="combobox"` with `aria-haspopup="listbox"`,
  `aria-expanded` and `aria-controls`.
- Listbox uses roving tabindex, `aria-selected` only on the selected option,
  and `aria-disabled` for disabled items.
- Selection changes are announced through a polite live region.

## Trade-offs / Limitations

- **Read-only only.** There is no text input for filtering; only type-ahead.
  For searchable selects, use a real `Input` + custom logic or wait for a future
  `Combobox` component.
- **No native form participation.** The component does not render a hidden
  `<input name="...">`; it is output-friendly, not form-submission-friendly.
- **Controlled/uncontrolled on both value and open state.** You can control the
  selection, the open state, both, or neither.
- **Slots must be direct children.** The keyboard hook reads the DOM at
  keydown time; wrapping items in arbitrary components breaks discovery.
